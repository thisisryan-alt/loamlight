# Loamlight: progress log

Working title **Loamlight**, an original 2D sandbox survival game (dig, build, craft, fight, explore). It can be renamed later; the name only appears in the product name, namespaces (`Loamlight.*`) and the executable.

This file is the resume point. A fresh session should be able to continue from here alone. `DESIGN.md` holds the design calls and data formats.

## How to run things

All commands are run from the repo root in PowerShell.

| What | Command |
|---|---|
| Open, resolve packages, compile | `./Tools/unity.ps1 import` |
| Regenerate settings, render pipeline, art import, scenes | `./Tools/unity.ps1 setup` (idempotent) |
| Re-render Blender sprites and pack the sheets | `./Tools/build_art.ps1` |
| Tests | `./Tools/unity.ps1 test -Platform EditMode` / `-Platform PlayMode` |
| Development player build | `./Tools/unity.ps1 player` → `Builds/Windows/Loamlight.exe` |
| Screenshot capture on the dev build | `./Tools/unity.ps1 capture -Scene PipelineDemo` → `Screenshots/PipelineDemo/` |
| Copy a capture into the docs | `& "$env:LOCALAPPDATA\Programs\Python\Python312-arm64\python.exe" Tools/docs_shots.py --capture Screenshots/PipelineDemo --milestone M0 --crop 300,80,980,620` |
| Art determinism check | `./Tools/build_art.ps1 -CheckDeterminism` |
| **Everything** (setup, tests, build, all captures) | `./Tools/verify.ps1` |

`unity.ps1` scans every Unity or player log for errors afterwards and exits non-zero if it finds any. A zero exit code from Unity alone is not trusted.

Environment: Unity 6000.4.11f1 (arm64 editor, "Supported" stream; the user chose it over installing an LTS), Blender 5.2.1, Python 3.12 arm64 with Pillow and numpy at `%LOCALAPPDATA%\Programs\Python\Python312-arm64\python.exe` (there is no `py` launcher). The machine is a Snapdragon X with an Adreno GPU and 16 GB of RAM, so it is a reasonable stand-in for a "mid-range laptop".

## M0: Setup (done 2026-10-12)

### Plan
1. Create the project on 6000.4.11f1 with URP (2D Renderer), Input System, Test Framework, Burst, Collections, Mathematics and 2D Sprite. Jobs ships in the engine core, so there is no separate package. Force Text serialization, Visible Meta Files, Unity `.gitignore`.
2. Write `Tools/unity.ps1` as the batch driver for import, setup, exec, test, player and capture, with log scanning after every run.
3. Write `ProjectSetup.RunAll`, an `-executeMethod` entry that builds every setting and asset from code: editor and player settings, the URP asset with the 2D Renderer data, quality levels and input handling.
4. Art pipeline, part 1. A Blender headless script models a low-poly miner and a calibration sphere, then renders an orthographic albedo pass and a camera-space normal pass for every frame. Pillow packs the frames into sheets with a JSON sidecar. The pipeline must be byte-deterministic.
5. Art pipeline, part 2. An editor importer applies point filtering, no compression, no mips, PPU 16, slices the sheets with stable sprite IDs, and assigns each normal map as the `_NormalMap` secondary texture.
6. A `PipelineDemo` scene, built from code: the animated miner, a calibration sphere, a flipped copy and a no-normal-map control copy, all under an orbiting colored Light2D in darkness.
7. A development player build with the `-llCapture <dir> -llScene <name>` debug flag: load the scene, take screenshots, write a report, quit.
8. EditMode tests for the import settings of every sheet, and a PlayMode test for the demo scene.
9. Write `DESIGN.md` and update this file.

### Done
- **Project.** Unity 6000.4.11f1 project at the repo root. Packages: URP 17.4.0 with the 2D Renderer, Input System 1.19.0 (the legacy input manager is off), Burst 1.8.30, Collections 6.4.0 (built-in), Mathematics 1.3.3, Test Framework 1.6.0, 2D Sprite 1.0.0 and uGUI. Force Text serialization, Visible Meta Files, Linear color space, and Unity `.gitignore`/`.gitattributes` files.
- **`Tools/unity.ps1`.** Runs import, setup, exec, EditMode and PlayMode tests, the player build and capture. Every run's log is scanned for errors.
- **`ProjectSetup.RunAll`.** Sets editor and player settings, sorting layers (`Background, Walls, World, Entities, Foreground, Overlay`), the URP asset with its 2D Renderer for every quality level, the art import and the scenes. It is idempotent: a second run leaves git clean.
- **Art pipeline.**
  - `Tools/blender/render_sprites.py` models the miner (idle 4, walk 8, jump 1, fall 1, use 4 frames) and a calibration sphere in code. It renders albedo and camera-space normals.
  - `Tools/art/pack_sheets.py` adds the outline, packs the sheet, writes the JSON sidecar and validates the sphere's normals.
  - `Tools/art/gen_tiles.py` generates the stone wall tile.
  - Two clean builds produce byte-identical output.
- **`ArtImport`.** Point filtering, no compression, no mips, PPU 16, stable sprite IDs, `_NormalMap` assigned as the secondary texture, and a `SpriteAnimationSet` per sheet.
- **PipelineDemo scene.** Generated by `SceneBuilder`. It contains the normal-mapped sphere, a control sphere without a normal map, a `flipX` sphere and two animated miners, each lit by a torch that orbits it, plus a teal accent light on a normal-mapped stone wall.
- **Debug capture flag.** `-llCapture <dir> -llScene <name>`. Each shot is verified from its pixels, and a negative control proves the verification can fail.
- **Tests.**
  - EditMode (23): import settings for every sheet, stable IDs and pivots, the normal map present as a secondary texture, animation sets, URP and project settings, sorting layers, and `LaunchArgs` parsing.
  - PlayMode (3): demo lights have normal maps enabled and target every layer, the orbit stays in sync, the miner animates, and animated frames carry the normal map.
- **Proof** is in `docs/screenshots/M0/`: four light angles, `contact_sheet.png` and `report.txt`.

### Measured (dev build, 1280×720, Snapdragon X / Adreno X1-85, D3D12, vsync off)
- PipelineDemo: average 2.3 ms per frame (437 fps), p95 4.5 ms; FrameTimingManager reports 2.3 ms CPU and 1.3 ms GPU. This is a tiny scene. Real numbers start in M1 with the 4200×1200 world.

### Decisions made in M0 (details in DESIGN.md)
- **Facing uses `SpriteRenderer.flipX`, never a negative scale.** The negative-scale path inverts normal Y in URP's 2D normals pass. This was found from the capture's pixel data, and a negative control guards it.
- **Normal maps:** the PNG has +Y up and +Z toward the viewer. Cycles' camera-space Z is negated when encoding.
- **Character frames are 64×64** with the pivot at the feet, `(0.5, 2/64)`. The game uses 16 PPU, and the camera reference resolution is 480×270 for the demo; the game camera will use 960×540.
- **Generated scenes are fingerprint-gated** so setup stays idempotent.

### Rough
- The demo is dark: mean frame luminance is about 15 of 255. That is intentional for a cave mood, but a gamma or exposure pass belongs in M3, together with the day/night cycle.
- The stone tile is a single 16 px variant, so repetition shows on large walls. M1 brings a proper tile atlas with variants and autotiling.
- Labels use the legacy uGUI `Text` with the built-in font. The real UI comes in M2 and M6.
- The Blender miner is deliberately simple: boxes, an icosphere head and a two-segment bevel.

### Known bugs / caveats
- **The Input System handler switch only applies after an editor or player restart.** It is set by setup and has not been exercised yet, because there is no input code. Player input starts in M1.
- **The first player build rewrote `Assets/Settings/Rendering/LoamlightURP.asset` and `Assets/DefaultVolumeProfile.asset`.** URP fills in shader prefiltering and default volume overrides. These changes were committed, and a second build left git clean. If a fresh `setup` ever recreates the URP asset, the first build will dirty it again.
- Capture timing is from a development build. Release-build numbers will be lower; M1 will report both.

## M1: Dig and move (done 2026-10-12)

The user asked for the whole game to be finished without milestone check-ins (2026-10-12). Each milestone is still finished, verified and committed before the next.

### Plan
0. **Spikes.**
   - Burst runs Burst-compiled in the ARM64 player.
   - A chunk MeshRenderer with Sprite-Lit-Default and the normal atlas passes the pixel verifier.
   - A Sprite Light2D whose cookie texture is updated at runtime lights tiles in color, aligned to the tiles.
   - `unity.ps1` also scans logs for Burst errors and leaks.
1. **Assemblies.** Core, Content, World, Player, plus a test that enforces the assembly graph. Content JSON (`tiles.json`, `walls.json`) goes through the importer into ScriptableObjects and the ContentDatabase.
2. **WorldData.** Chunk-major SoA NativeArrays with accessors.
3. **Worldgen**, Burst and seeded: surface, dirt, stone, caves, background walls, grass. Plus a determinism test and timing.
4. **Tile atlas** with autotile masks and variants (Pillow), normal atlas and an importer.
5. **Chunk mesher** (Burst, MeshData), streaming and a pooled renderer for chunks in view. Mesh-vs-Tilemap rebuild benchmark.
6. **Tile collision** and a pure `PlayerMotor`: acceleration, variable jump, coyote time, jump buffer, step-up. EditMode tests.
7. **Player** with Input System actions behind `IPlayerInput`, a camera follow and the sprite animator.
8. **Mining and placing** with reach, progress and cracks. Basic SFX from the Python synth.
9. **Light map v1**: sky and the cookie Sprite Light2D, plus a torch emitter so caves are dark.
10. **Save v1**: world plus player position. Round trip and a committed fixture.
11. **Game scene**, scenario capture and full-world perf capture. Update DESIGN.md and PROGRESS.md.

### Done
- **Spikes, all verified in the ARM64 dev player (`capture -Scene TileLab`, 6 pixel-checked shots).**
  - Burst runs compiled in the player.
  - The chunk-mesh calibration sphere shades identically to the SpriteRenderer sphere: mean difference 0.0.
  - The cookie Sprite Light2D carries colour, is aligned to tiles and leaves unlit tiles black.
  - Propagation works: sky light enters from above, a torch lights its cave, deep rock stays black.
- **Content pipeline.** `Assets/Content/Data/{tiles,walls,items}.json` → `ContentImport` (validated: unknown references fail the import) → one ScriptableObject per definition plus `ContentDatabase` in Resources. Numeric IDs follow sorted names; saves remap by name.
- **WorldData.** Chunk-major SoA NativeArrays (32×32 chunks) with dirty flags that also mark neighbour chunks used for autotiling.
- **Worldgen (Burst, seeded):**
  - surface hills, dirt over stone with pockets, clay seams;
  - worm tunnels, caverns that open up with depth, small pockets, and only a few cave mouths at the surface;
  - background walls, grass.
  - The full 4200×1200 world generates in about 60 ms in the editor and about 75 ms in the player.
- **Tile atlas (`Tools/art/gen_atlas.py`).** Autotiling with 16 air masks × 3 variants, bevelled height normals, outlines and rounded corners, an emission atlas, item icons and crack frames. The calibration object is sliced from the Blender sheet.
- **`Loamlight/Tile Lit` shader.** URP 2D lit path without sprite-only per-draw data, plus emission.
- **Chunk rendering.** Burst `ChunkMeshJob` into `Mesh.MeshData`, two meshes per chunk (walls and blocks). The streaming `ChunkRenderer` keeps only visible chunks (pooled), rebuilds dirty ones under a budget, nearest first.
- **Collision.** Tile height-field (full, half, slopes) with 1-tile step-up, one-way platforms, ceiling stops and sub-stepping (no tunnelling).
- **Movement.** Pure `PlayerMotor`: acceleration and deceleration, variable jump (cut on release), apex hang, coyote time 0.1 s, jump buffer 0.12 s. Fixed 60 Hz step with interpolation.
- **Player.** Input System actions built in code behind `IPlayerInput`; `ScriptedPlayerInput` for scenarios.
- **Mining and placing.**
  - `ToolUser`: reach, hardness and tier gating, a crack overlay, hit and break SFX.
  - `WorldEdits`: anchoring rules, multi-tile objects, and breaking anything left unsupported.
  - Block, wall and torch placement.
- **Light map** (`LightMapSystem`): 20 Hz Burst flood fill (sky columns plus emitters, solids attenuate) into a cookie Sprite Light2D, plus pooled normal-mapped highlight point lights on nearby emitters.
- **Inventory.** `ItemContainer` with 50 slots, the first 10 as the hotbar; HUD hotbar with icons and counts.
- **SFX.** `Tools/audio/synth_sfx.py` (12 sounds, 28 variants) → `AudioImport` → `SfxLibrary`. `Sfx` plays them with panning and rate limiting.
- **Save v1.** Header, name palettes and RLE arrays. Deflate is unusable because the ARM64 player lacks MonoPosixHelper. Write-then-copy. A committed fixture, `Assets/Tests/Fixtures/world_v1.lmw`, must load forever.
- **Game scene.** `GameBootstrap` composition root plus `GameScenarioDirector`. Launch flags: `-llSeed`, `-llWorldSize WxH`, `-llLoad <path>`, `-llScenario m1|perf`.

### Verified
- **EditMode, 67 tests:**
  - layout and dirty flags;
  - worldgen determinism, layers and timing;
  - collision (falls, tunnelling, step-up, slopes, half blocks, platforms, ceilings);
  - motor (run speed, jump heights, coyote time, buffer, fall distance);
  - inventory;
  - saves (round trip, garbage rejection, v1 fixture);
  - MiniJson, content validation, atlas coverage, icons;
  - the assembly graph.
- **PlayMode, 5 tests:** the Game scene boots and the player stands, a mesh-vs-Tilemap benchmark, and the PipelineDemo tests.
- **`capture -Scene Game -Scenario m1`**, in the dev player, all checks green:
  - spawn on the surface;
  - full running speed within 0.25 s, then 19 tiles walked in 2 s over terrain, then a clean stop;
  - held jump 5.1 tiles versus a 2.0-tile tap;
  - mining (with drop and sound), digging 10 tiles down, placing a block (consumes one) and a torch (light 0.35 → 1.00);
  - save and load round trip with the same hash: save 83 ms, load 57 ms, 2.0 MB.

### Rough
- The pickaxe has no icon yet; Blender item icons arrive in M2.
- The surface is a stair-step outline with no natural slopes. A smoothing pass that places slope tiles is planned for M5.
- The light map is diamond-shaped (directional sweeps); bilinear filtering softens it, but it shows on open sky edges.
- Mined items go straight into the inventory (`InventoryDropSink`). M2 adds item pickups.

### Known bugs / caveats
- Mining aims at the tile under the cursor but doesn't require line of sight, so a player can mine through a 1-tile wall. Terraria behaves the same way; noted as a design choice.
- Frame times come from a development build at 1280×720. The release-build perf run is part of M6.

## M2: Build and craft (done 2026-10-12)

### Plan
1. Item pickups: drops spawn magnetised pickup entities; inventory overflow stays on the ground.
2. Inventory UI: Esc/E opens a 50-slot grid with drag and drop, a trash slot and tooltips. Pixel font generated from Python glyphs, plus pixel-art UI sprites.
3. Crafting:
   - stations are tile objects (workbench, furnace, anvil);
   - recipes in `recipes.json`, with stations required within 4 tiles;
   - a crafting panel listing what can be made;
   - a `Crafting` assembly holding the pure logic and tests.
4. Building tools (pillar 3):
   - ghost preview (green or red);
   - drag places a line, Shift-drag fills a rectangle;
   - hammer: block shapes cycle full → half → slope right → slope left, and it removes walls;
   - Ctrl+Z undoes the last 20 placement batches, refunding the items.
5. Doors (toggle with Interact, solid when closed), platforms (one-way), furniture (table, chair, chest with storage, bed sets the spawn point), trees and wood (axe), ores and bars (copper and iron) so the recipes have inputs.
6. Blender item and furniture art: tool, weapon and item icons, furniture renders sliced into atlas cells.
7. Scenario `m2`: pick up drops, craft a workbench → table and chair, build a house by line and rectangle, hammer slopes, undo, open a door, store items in a chest, save and reload with the chest contents intact.

### Done
- **Content.**
  - 23 tiles: ores, trees and canopies, grass decor, platforms, a workbench, furnace, anvil, table, chair, chest, door and bed.
  - 27 items: copper and iron tools, a hammer, bars, furniture.
  - 18 recipes.
  - All in JSON, validated on import.
- **Blender `render_objects.py`.** Furniture, stations, doors (closed and open) and tree canopies get albedo, normal and emission passes, sliced into atlas cells; the furnace fire glows. Item icons are rendered from the low-poly models. Pillow adds bark, platform and grass-decor styles. Generated in Python: a 5×7 bitmap pixel font (95 glyphs, imported as a Unity Font) and a 9-slice UI kit.
- **Worldgen.** Copper and iron veins in depth bands, plus 252 trees and tall grass on the default seed. Decoration runs single-threaded, so it stays deterministic.
- **Item pickups (`PickupSystem`).** Drops pop out, fall, settle, merge, and are magnetised within 4.5 tiles if there is room. The rest stays on the ground for 10 minutes.
- **Crafting (`Loamlight.Crafting`).** `CraftingBook` is pure logic. It offers recipes whose station is within 4 tiles, crafts all-or-nothing, and handles batch crafting with Shift (×10).
- **Building (pillar 3, `ToolUser`).**
  - Ghost preview: green when valid, red when not, and objects show every cell.
  - Click places one tile, drag places a Bresenham line, Shift-drag fills a rectangle. Releasing commits exactly the previewed tiles.
  - Batches of up to 400 tiles.
  - Ctrl+Z undoes the last 20 batches and refunds the items, provided the tiles are untouched.
  - The hammer cycles full → half → slope right → slope left, and on an empty tile it knocks the wall down.
  - Axes fell trees: the whole trunk and canopy cascade, 2 wood per trunk cell.
- **Doors, chests and beds.**
  - Doors open with right-click. The collision grid treats an open door as passable, and a door won't close on the player.
  - Chests hold 30 slots, open with right-click, support shift-click quick-move, can't be broken while full, and are saved.
  - Beds set the spawn point (saved).
- **UI.**
  - HUD hotbar using the UI kit, plus toasts.
  - Inventory screen (E or Tab): 50 slots, trash, tooltips, a cursor stack, a chest panel, and a crafting panel with ingredient have/need. The item logic is a separate `InventoryModel`, unit-tested.
- **SFX.** Doors, chests, crafting, UI open and close, pickups. 19 groups, 35 clips.
- **Save game JSON** now holds the player, inventory, spawn point and chests. The save format is still v1.
